Methodology

Built so a CTO can check every number. Each report links its raw results.json: every prompt, run, tool call and grade.

Prompts

Generated from public information about the company and reviewed by a person, or taken from real logs. Each prompt has a type (lookup, freshness, multi-hop, list-building, regulation) and a reference answer with grading notes that the judge uses.

Same agent, different search

One agent runs every prompt once per provider: the same model (resolved once and pinned for the whole audit), the same instructions and the same budget of tool calls and seconds. Each provider exposes one search tool and one page-reading tool. A run that errors or hits its budget is kept and counts as not correct; runs are never dropped.

Keenable routed

Jev (typesafe/jev-1.13) answers one choice question about the query: search or select. Search is anything on one page, including a list. Select is a row that is not on that page, from a different primary document. Select is for work where latency is not mission critical: not a chat reply someone is waiting on, and fine for background work that can wait about 90 seconds. The agent then has only that tool. The run records the choice and its confidence.

Grading

A judge model checks every answer against the reference on four criteria: answers the prompt, facts correct, sources support it, up to date. All four pass = ✓ correct; the first plus all but one = ◐ partly correct; otherwise ✗ wrong. The report lists any grade that does not match its own checks. Agreement with human graders is published once answers have been hand-graded; until then the report says "not measured yet".

Scoring

Accuracy alone treats a 1-second answer and a 3-minute answer as equal. So each answer gets a value score: a wrong answer scores 0; otherwise accuracy credit (✓ = 1, ◐ = 0.5) × (accuracy weight + cost weight × cheapness + speed weight × speed) ÷ total weight. Cheapness and speed are relative to the cheapest and fastest answer on that prompt that was not wrong, so a fast wrong answer never lowers the score of a correct one. Defaults: accuracy 60, cost 25, speed 15; change them with the sliders on a report.

Is a difference real?

Providers answer the same prompts, so accuracy gaps are tested pair-wise: an exact McNemar test on the prompts only one of the two got right (◐ counts as not correct), with a Holm correction when the leader is compared with several providers. "Tied" means the gap to the most accurate provider could be chance. Head-to-head comparisons also show a paired bootstrap interval for the difference. The Pareto chart rings providers that no other provider beats on both accuracy and cost.

The headline is computed from these tests, never written by hand. With fewer than 30 prompts, or when one provider failed more than half its runs, it says there is not enough evidence yet.

Implementation guide

For each prompt type the same paired test compares Keenable search with Keenable SELECT. A type routes to the winner only when the difference is clear (p < 0.05); otherwise it is marked "lean · re-test" and defaults to search, which is cheaper and faster. Types with fewer than 10 prompts get no decision. When another provider scores clearly higher than the Keenable route on a type, the guide says so.

Cost

Cost per prompt is search spend plus agent model tokens for that run. Where a provider's response does not report its price, a list price is used and the number is marked ~; any estimated input makes a derived number (such as monthly cost at volume) estimated too.

What it does not measure

Generated prompts approximate a workload. Results hold for this agent, this model and this date. Prices change.
